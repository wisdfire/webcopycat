# WebCopyCat 요구사항 정의서

## 1. 배경 및 문제

| 문제 | 설명 |
|------|------|
| 전체 선택 복사의 잡음 | `Ctrl+A` → 복사 시 메뉴, 배너, 댓글, 푸터까지 복사됨 |
| 드래그 복사의 번거로움 | 긴 패치노트를 드래그로 선택하는 데 시간이 오래 걸림 |
| 복사 방지 사이트 | 네이버 카페 등 일부 사이트는 드래그·우클릭·복사를 막아 둠 |

**목표:** 확장프로그램 버튼 한 번으로 **게시물 본문만** 클립보드에 복사한다.

예시 대상
- 넥슨 포럼: `https://forum.nexon.com/maplestoryidle-kr/board_view?board=6698&thread=3550026` → 패치 내용만 복사
- 네이버 카페: `https://cafe.naver.com/omfgluckyme/477229` → 복사 방지 상태에서도 본문 복사

## 2. "HTML을 읽어서 긁으면 되지 않나?"에 대한 분석

결론: **가능하며, 이 방식이 이 확장프로그램의 핵심이다.** 다만 아래 세 가지를 감안해야 한다.

### 2.1 서버 HTML이 아닌 "렌더링된 DOM"을 읽어야 한다
두 예시 사이트의 원본 HTML을 직접 받아 보면 본문이 없다.
- 넥슨 포럼: 원본 HTML은 약 10KB짜리 껍데기(`.view-box` 같은 빈 틀)뿐이고 본문은 JavaScript로 나중에 채워진다.
- 네이버 카페: SPA 구조라서 본문이 JavaScript로 렌더링된다. 구형 레이아웃은 `cafe_main` iframe 안에 본문이 있다.

→ 서버에 HTML을 다시 요청하는 방식은 실패한다. **확장프로그램의 content script가 사용자가 보고 있는 페이지의 DOM을 그대로 읽어야** 한다. 이렇게 하면 로그인이 필요한 카페 글도 그대로 읽을 수 있다.

### 2.2 복사 방지는 DOM 읽기에 영향을 주지 않는다
복사 방지는 대개 다음 방법으로 구현된다.
- CSS `user-select: none`
- `copy`, `selectstart`, `contextmenu`, `dragstart` 이벤트 차단

이것들은 **사용자의 마우스·키보드 동작만** 막는다. 확장프로그램이 `element.innerText`로 텍스트를 읽고 확장프로그램 쪽에서 클립보드에 쓰면 이 방어를 거치지 않는다. 우회 코드도 따로 필요 없다.

### 2.3 "어디가 본문인가"를 판단하는 것이 진짜 문제
모든 사이트에서 동작하려면 본문 영역을 자동으로 찾아야 한다. 방식은 두 겹으로 둔다.

1. **사이트 전용 규칙 (우선):** 주요 사이트는 CSS 선택자로 본문 영역을 지정한다. 가장 정확하다.
   - 예: 넥슨 포럼 `.view-box`, 네이버 카페 `.se-main-container` (실제 페이지에서 확인 후 확정)
2. **범용 자동 추출 (기본값):** 규칙이 없는 사이트는 Mozilla **Readability**(Firefox 읽기 모드 엔진)로 본문을 추출한다. 텍스트 밀도와 태그 구조로 본문을 점수화하므로 뉴스, 블로그, 게시판 대부분에서 동작한다.
3. **보조 수단 (2단계):** 자동 추출이 틀린 경우 사용자가 마우스로 영역을 직접 클릭해 고르는 "영역 선택 모드".

## 3. 기능 요구사항

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| F1 | 툴바 아이콘을 클릭하면 현재 페이지 본문을 즉시 복사한다 (팝업 없이) | 필수 |
| F2 | 우클릭 메뉴에서 "본문 복사"를 실행할 수 있다 | 필수 |
| F3 | 단축키로 실행할 수 있다 (기본 `Alt+Shift+C`, `chrome://extensions/shortcuts`에서 변경 가능) | 필수 |
| F4 | 복사 형식은 **일반 텍스트**이며 문단과 줄바꿈을 유지한다 | 필수 |
| F5 | 이미지는 제외하고 텍스트만 복사한다 | 필수 |
| F6 | 사이트 전용 규칙이 있으면 우선 적용하고, 없으면 Readability로 추출한다 | 필수 |
| F7 | 본문이 iframe 안에 있어도 추출한다 (네이버 카페 구형 레이아웃) | 필수 |
| F8 | 복사 방지가 걸린 페이지에서도 동작한다 | 필수 |
| F9 | 성공/실패를 아이콘 배지(`✓` / `!`)로 1~2초간 표시한다 | 필수 |
| F10 | 연속된 빈 줄, 앞뒤 공백 등 불필요한 공백을 정리한다 | 필수 |
| F11 | 영역 선택 모드: 자동 추출이 틀렸을 때 사용자가 직접 영역을 클릭해 복사 | 2단계 |
| F12 | 게시물 제목을 본문 맨 위에 포함할지 선택하는 옵션 | 2단계 |

## 4. 비기능 요구사항

| 항목 | 기준 |
|------|------|
| 속도 | 클릭부터 복사 완료까지 체감 1초 이내 |
| 권한 최소화 | `activeTab`, `scripting`, `contextMenus`, `offscreen`, `clipboardWrite`만 사용. 모든 사이트 접근 권한(`<all_urls>`)은 요청하지 않음 → 스토어 심사와 사용자 신뢰에 유리 |
| 개인정보 | 데이터를 수집하거나 외부로 전송하지 않음. 네트워크 요청 없음 |
| 호환성 | Chrome 최신 버전(Manifest V3). Edge, Whale 등 Chromium 기반 브라우저도 동작 |
| 유지보수 | 빌드 도구 없이 소스 폴더를 그대로 로드하고 패키징 |

## 5. 제약 및 리스크

| 리스크 | 대응 |
|--------|------|
| 사이트 개편으로 전용 선택자가 깨짐 | 전용 규칙 실패 시 Readability로 자동 대체 |
| Readability가 댓글이나 목록을 본문으로 오인 | `charThreshold`를 100자로 낮춤 (기본 500자는 짧은 한글 글에서 댓글까지 포함됨), 사이트 전용 규칙 추가, 2단계 영역 선택 모드 |
| 툴바 클릭 직후 페이지에 포커스가 없어 `navigator.clipboard` 실패 | offscreen 문서에서 `execCommand('copy')`로 쓰기 (`clipboardWrite` 권한 필요, 설치 경고 없음) |
| `chrome://`, 웹스토어 페이지에는 스크립트 주입 불가 | 실패 배지로 안내 (브라우저 정책상 불가피) |
| 복사 방지 우회에 대한 저작권·정책 이슈 | 스토어 설명에 "우회"를 전면에 내세우지 않음. 개인적 이용 목적임을 명시하고 저작권 책임은 사용자에게 있음을 고지 |

## 6. 범위 밖 (현재 하지 않음)

- HTML, 마크다운 등 서식 있는 복사
- 이미지 복사 및 이미지 URL 포함
- 복사 기록 저장, 클라우드 동기화
- 서버, 회원가입, 결제
